# macOS 本机代码任务执行服务

用 FastAPI 构建的本机代码检查、单元测试与归档打包服务，附带同源托管的 **TaskRunner 可视化工作台**。支持三种代码来源（**预置仓库 ID**、**在线修改代码快照**、**本地 `.zip` 压缩包上传**），在隔离的 `0700` 临时工作目录中通过独立会话与 `kqueue` 监管真实子进程组，运行中可通过 SSE 实时流或轮询读取日志、随时取消，完成后可预览结构化报告并下载可执行构建产物。开发与验收环境为 Apple Silicon macOS 26.6.2、Python 3.12。

## 启动

在仓库根目录使用 uv 安装锁定的依赖并启动：

```bash
uv sync --locked --python 3.12
uv run --locked python -m task_service
```

浏览器打开 **[TaskRunner 一体化工作台](http://127.0.0.1:8765/)** 即可在同一页内完成全部观测与操作：
- **实时资源与沙箱零泄漏遥测**：实时监控宿主机负载、双并发执行槽及任务子进程组（PGID）的存活进程数、RSS 内存与 CPU 占用、FIFO 排队延迟、`work/<id>` 沙箱零残留状态及 SQLite WAL 存储分布；
- **内置 5 大模拟任务仓库与自由派发**：清晰展示每个预置任务的职责说明，支持直接组合 `lint` / `test` / `build` 提交，或打开「在线改码 / 本地 `.zip` 上传」工作区在隔离沙箱运行自定义代码；
- **6 大核心能力演示与动态架构流程图**：显式列出每项演示调用的具体任务配方与验证的底层能力（含双槽并发与队列补位、进程组取消、单调时钟超时、`64 KiB` 日志限流排空等），配套 SVG 流程图与 SSE 实时终端同步联动；
- 也可访问 [OpenAPI 交互文档](http://127.0.0.1:8765/docs) 或使用下方的 `curl`。服务仅监听本机回环地址，可用 `--port` 和 `--data-dir` 指定端口和数据目录（默认 `.task-service/`），重启使用同一目录即可恢复并查询历史任务。按 Ctrl-C 优雅关闭服务。

## 重放演示和验收

下面两条命令会自行启动独立服务，分配临时端口和数据目录，退出时自行清理。可以在日常实例运行期间执行。

```bash
uv run --locked python scripts/demo.py
uv run --locked python -m unittest discover -s tests/e2e -v
```

演示会运行一个通过的测试、一个真正失败的断言、一个带子进程的长测试，最后下载并执行构建归档，输出 `Hello, Mac!`。E2E 额外从宿主机验证进程退出、临时目录删除、日志截断、重启恢复和并发上限。进程与文件权限测试使用普通 macOS 用户运行。

## 手动提交

```bash
curl -i http://127.0.0.1:8765/tasks \
  -H 'Content-Type: application/json' \
  -d '{"project_id":"hello","type":"build","timeout_seconds":30}'
```

创建成功返回 202 和带有任务 ID 的 Location 响应头。将下面的 ID 换成返回值即可查看执行过程。完成构建后再下载归档。

```bash
id='替换为返回的任务 ID'
curl "http://127.0.0.1:8765/tasks/$id"
curl "http://127.0.0.1:8765/tasks/$id/logs"
curl "http://127.0.0.1:8765/tasks/$id/artifacts"
curl -f -o /tmp/task-demo.pyz "http://127.0.0.1:8765/tasks/$id/artifacts/app.pyz"
uv run --locked python /tmp/task-demo.pyz
```

| 预置项目 | 模拟场景与适合展示的操作 |
| --- | --- |
| `hello` | 问候与发布模块：`lint` 语法校验，`test` 运行 4 项通过的单元测试，`build` 生成可运行的 `app.pyz` |
| `broken` | 订单计费模块：`test` 中前 2 项通过、第 3 项触发 `20 != 21` 断言失败（支持在前端一键「在线改码」修复重跑） |
| `slow` | 长耗时分片扫描：派生忽略 `SIGTERM` 的子进程并逐秒输出进度，可演示自动/手动取消或 `2s` 超时看门狗 |
| `pipeline` | 约 `2.2s` 的多阶段数据处理流水线并自检沙箱文件隔离，用于演示双执行槽并发与 FIFO 队列自动补位 |
| `logflood` | 瞬间输出 `96 KiB` 压测追踪流，用于验证 `64 KiB` 日志截断标志与持续排空管道防死锁 |

服务同时执行 2 个任务，最多再接收 32 个排队任务。单任务保存前 64 KiB 日志，构建产物上限 5 MiB，终态数据保留七天。可用 `--projects` 指定维护者控制的预置项目目录；有测试的项目应包含 `tests/__init__.py`。这些项目以当前账号权限运行，仅适用于可信代码。

设计文档说明了取消与完成的竞态、终态发布和故障恢复；AI 使用记录包含一次从错误结果追到系统调用的实测过程。[设计与边界](docs/DESIGN.md) · [AI 使用记录](docs/AI_USAGE.md)

# AI 效能平台实习考察题：代码任务执行服务

本仓库是面向「AI 效能研发实习生」的考察题。候选人需要 fork 本仓库，在 3 天内实现一个可运行的小型服务，并在面试中演示与继续修改。

## 考察目标

我们希望评估候选人的以下能力：

- 理解需求并把模糊问题转化为可运行的工程实现
- 后端接口设计、状态管理与错误处理
- 进程、临时目录、日志等系统资源控制
- 基本的权限与安全设计
- 测试、复现与文档能力
- 是否能用 AI 工具提升效率，并验证 AI 生成结果

## 题目

请实现一个**代码任务执行服务**，用于在隔离的工作目录中执行代码检查、测试或构建任务，并支持查询任务状态、日志与产物。

### 基本功能

至少实现以下接口：

1. 创建任务

```
POST /tasks
```

请求包含：

- 代码来源，例如本地压缩包、预置仓库 ID 或指定目录
- 任务类型，例如 `lint`、`test`、`build`
- 可选的超时时间

2. 查询任务状态

```
GET /tasks/{id}
```

返回：

- 状态：`queued` / `running` / `succeeded` / `failed` / `timeout` / `cancelled`
- 开始与结束时间
- 退出码与错误信息

3. 查看任务日志

```
GET /tasks/{id}/logs
```

要求：

- 记录标准输出与错误输出
- 日志有大小上限
- 任务运行中也能读取已有日志

4. 取消任务

```
POST /tasks/{id}/cancel
```

5. 查询产物

```
GET /tasks/{id}/artifacts
```

任务完成后可返回测试报告、构建结果或压缩包。

### 安全与可靠性要求

- 只允许执行预先定义的任务类型，不允许直接执行任意 shell 字符串
- 每个任务必须有超时
- 日志不能无限增长
- 任务完成后必须清理临时文件和子进程
- 同一时间可并发执行多个任务
- 需要考虑重复取消、任务不存在、服务重启等情况

### 技术栈

可以使用 Rust、Python 或 Go 中任意一门语言。允许前端，但不是硬性要求。

### 允许使用 AI 工具

可以使用 AI 辅助编码，但需要在 `AI_USAGE.md` 中说明 AI 参与了哪些部分，以及你如何验证 AI 生成的结果。
